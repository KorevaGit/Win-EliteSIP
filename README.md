# EliteSIP для Windows

SIP-софтфон под Windows 10/11 для Asterisk. Порт macOS-версии
(`../Swift EliteSIP`) на C# и .NET 10. Стек свой: SIP и RTP написаны с нуля,
без PJSIP, без Electron, без внешнего бэкенда. Один процесс, ноль IPC.

Область та же, что у оригинала — только то, что нужно оператору:
**конференция, удержание, DTMF, DTMF-макросы, перевод и история звонков**. Нет
контактов, нет голосовой почты, нет видео.

Плюс то, ради чего проект в основном и начат: **защита приёма горячих лидов от
автокликеров**. Менеджер, автоматически принимающий вызов из очереди раздачи,
получает больше лидов, не находясь за рабочим местом, и лид уходит в тишину.
Рандомизация окна — часть этой защиты, а не косметика.

## Решения

| | |
|---|---|
| Платформа | .NET 10 LTS, WPF. Windows 10 22H2 и Windows 11 |
| Транспорт | боевой Asterisk использует UDP; TLS + SRTP (SDES) поддерживаются отдельно |
| Кодеки | G.722 с fallback на G.711 PCMU/PCMA, 20 мс, + telephone-event (RFC 4733) |
| Сервер | Asterisk 13.38.3 под FreePBX, драйвер `chan_sip` |
| Аудио | event-driven WASAPI, эхоподавление своим блоком — см. этап W0 плана |
| Окна | панель софтфона 280×500 · плавающее окно входящего 320×212 · настройки |
| Конференция | ConfBridge на стороне Asterisk |
| Перевод | REFER + Replaces, плюс серверные DTMF-коды через макросы |
| Дизайн | тот же макет Figma, что у macOS-версии |

## С чего начинать

**Читать [docs/PORT-PLAN.md](docs/PORT-PLAN.md).** Там порядок работ, приёмка
каждого этапа и риски. Первый этап — W0, прототип аудиотракта: он блокирующий,
и начинать с чего-то другого нельзя.

Документация, объясняющая **почему** поведение именно такое, живёт в
macOS-проекте (`../Swift EliteSIP/docs/`) и переписыванию не подлежит: аудиотракт,
защита от автокликеров, удержание и DTMF, линии, перевод, локализация,
удалённый доступ.

## Сборка и тесты

```
dotnet build
dotnet test
```

## Конфиденциальность

**В Git нельзя пароли.** Боевые адреса, добавочные, номера очередей и коды
переводов лежать могут — репозиторий внутренний. Административный пароль и код
восстановления вшиваются в релизную сборку из конфига вне Git; файлы
`*.local.json` в `.gitignore` намеренно.
